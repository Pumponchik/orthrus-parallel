# Воспроизводимость

## Что можно воспроизвести из чистого репозитория

- Инференс всех шести режимов через `python -m orthrus_parallel`.
- Параметры модели и среды: `configs/checkpoint.json`, `.python-version`, `pyproject.toml`, `uv.lock`.
- Результаты исходного измерения: полная таблица 288 измерений, агрегаты и интервалы. `check_repository.py` пересчитывает скорости из таблицы.
- Проверку масок, состояния кеша, EOS, коротких лимитов и запуска всех режимов на настоящем checkpoint.
- Повторное обучение двух линейных голов, если предоставить сохранённые состояния в описанном ниже формате.

Исходные времена из README измерены 12 октября на старом экспериментальном runtime. Очищенный runtime проверен 14 октября на совпадение token IDs и выборов селектора. Это регрессия корректности; **скорость нового кода заново не измерялась**. Изменён служебный код, поэтому нельзя приписывать ему старые времена с точностью до сотых.

## Проверить runtime

После установки окружения и загрузки checkpoint:

```bash
./lab run --locked python tests/validate_runtime.py \
  --checkpoint models/ZaryaOrthrus-0.6B/6c93071b27ab0d2061007dda0416f0439ed4d7df \
  --output runs/validation.json
```

Опциональный `--reference-root /path/to/original-experiment` включает непосредственное сравнение с исходным кодом. Без него сохраняются самостоятельные численные проверки и real-model smoke; поле сравнения с исходником будет `null`, а не выдуманное успешное сравнение.

## Обучить селектор

```bash
./lab run --locked python scripts/train_selector.py \
  --data archive/cv10_20261012/selector_data \
  --output runs/retrained_selector
```

Каждая папка `shard*` должна содержать:

- `receipt.json` со `state: complete`;
- пары `task.npz` и `task.json`;
- NPZ: `x` размера `[states, 16, 17]`, `r` размера `[states]` (0…15), `rank` размера `[states]` (0…8);
- JSON: уникальный `id` запроса и `split`, равный `train` или `validation`.

Сохранённые признаки должны быть получены до проверки, а метки — из последующей AR-проверки. Метки ранга должны соответствовать **тому же** правилу исключения proposal и top-8, что использует inference. Признаки и токены нельзя смешивать между разными checkpoint. Точные формулы приведены в [selector.md](selector.md).

Новые веса записываются в новый каталог; поставляемые веса не перезаписываются. В CLI по умолчанию закреплён селектор `selectors/zarya_06b`; новые веса можно передать конструктору `LinearSelector` в Python после проверки.

## Локальный архив исходного опыта

В рабочей папке пользователя сохранён `archive/cv10_20261012/`: все 391 исходный файл перенесены побайтово, включая код, обучающие состояния, полные token IDs, логи и контрольные суммы. `archive/relocation.json` фиксирует перенос; проверка сверяет каждый файл.

В архиве `design.json` — замороженный дизайн, `benchmark.py` — точный код замера, `analyze.py` — bootstrap-анализ, `runtime_support.py` и `bundle/` — исходный runtime. Относительные пути внутри архива сохранены. Для повторного запуска нужны Linux/CUDA-окружение и checkpoint по пути, ожидаемому исходным `runtime_support.py`; старые выходные папки намеренно защищены от перезаписи. Для нового полного опыта нужно создать отдельную рабочую копию и новые выходы, а не запускать pipeline поверх результатов.

Этот архив **не входит в Git и экспорт**: сырые исследовательские данные и многочисленные старые варианты остаются локально. Экспортированный репозиторий содержит читаемый рабочий код, итоговые маленькие веса и числовые доказательства результатов, но не претендует на побайтовый архив всей истории.

## Как заново измерять скорость

Используйте `benchmarks/prompts.json`, одни и те же настройки и физическую GPU для сравниваемых режимов. Загрузите модель один раз, прогрейте каждый режим на отдельном запросе, перемешивайте порядок методов и синхронизируйте CUDA до/после каждого измерения. Считайте реально выданные токены и сохраняйте token IDs, а не только скорость. Не сравнивайте отдельные холодные запуски CLI как benchmark.

Начало замера — перед prefill. Признаки, выбор ветвей и fallback должны входить во время. Загрузка checkpoint, токенизация входа и декодирование текста — снаружи. Для интервалов ресемплируйте запросы целиком, сохраняя методы и повторы вместе. Не считайте два greedy-повтора двумя независимыми запросами.
