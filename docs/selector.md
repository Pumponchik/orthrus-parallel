# Линейный селектор: формулы и метки

Блок содержит текущий якорь и 15 предложений. `r = 0…15` — число принятых предложений, то есть граница следующего якоря. Вход классификаторов `X` имеет размер `16 × 17`; порядок признаков зафиксирован в `draft_features`.

Для каждой головы независимо:

```text
Z = (X - mean) / scale
P = softmax(Z @ W + b, dim=-1)
```

`W_accept` имеет размер `17 × 2`, `b_accept` — 2. `W_rank` — `17 × 9`, `b_rank` — 9. `mean` и `scale` — 17-мерные векторы; scale ограничен снизу 0.1 при обучении. В NPZ веса называются `p0` (W) и `p1` (b).

## Вероятность границы

Обозначим `h_j = P_accept[j, 1]` для `j = 0…14`. Тогда:

```text
S_0  = 1
S_r  = product(h_j, j < r)
P(R=r)  = S_r * (1 - h_r),  r < 15
P(R=15) = S_15
```

Это условные вероятности продолжения принятого префикса, а не предположение о независимом принятии всех 15 токенов. Модель приближает их из признаков draft, без будущих результатов проверки.

## Вероятность пары

`q_rk = P_rank[r,k]`, где `k = 0…7` — ранг альтернативы, `k=8` — OUTSIDE.

```text
J_rk = P(R=r) * q_rk                 # [16, 9]
calibrated = softmax(log(max(J, 1e-12)) / temperature)  # по всем 144 исходам
scores = calibrated[:, :8]           # [16, 8]
```

В текущих весах temperature = 1.0. Оценки EOS-кандидатов обнуляются: после EOS продолжение не нужно. Берутся 48 максимальных оценок; при точном равенстве сохраняется порядок «граница, ранг». Конкретный token ID извлекается из отдельно построенной таблицы top-8. Ни embedding кандидата, ни его ID не подаются линейным головам. Следовательно, голова ранга различает ранги через статистики всей строки, а не через семантику конкретного кандидата.

Для `r < 15` из кандидатов предварительно исключается предложенный greedy-токен этой позиции: при остановке на ней AR должен выбрать другой токен. В последней строке исключения нет. OUTSIDE остаётся в нормализации, но ему не соответствует вычислимая ветвь.

## Обучающие метки

Состояние собирается до AR-проверки. После неё известны истинное `r` и корректирующий/bonus-токен `x`.

- Для головы принятия создаются строки `j = 0…min(r,14)`. Метка 1 при `j < r`; метка 0 при `j = r < 15`. После первой остановки меток принятия нет.
- Для головы ранга используется только строка `X[r]`: ранг фактического `x` среди top-8 альтернатив, либо класс 8. Для завершившегося ответа используется OUTSIDE, поскольку продолжение не требуется.
- Каждый запрос имеет одинаковый суммарный вес в функции потерь, независимо от числа собранных состояний/строк.
- Обе головы минимизируют взвешенную cross-entropy с L2-регуляризацией матрицы W; 500 шагов Adam, learning rate 0.03.
- Регуляризация выбирается из 0.001, 0.01, 0.1 по валидации: выбраны 0.001 для принятия и 0.01 для ранга. Затем по валидации выбирается температура объединённого распределения.

Признаки нормализуются по train-строкам, валидация используется для выбора гиперпараметров, тестовые запросы скорости не используются. Это небольшой селектор, обученный на HumanEval-состояниях именно ZaryaOrthrus-0.6B FP16; его нельзя автоматически считать подходящим для другого checkpoint.
